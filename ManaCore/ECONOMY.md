# ManaCore 1.3.0 經濟系統設計

> 主軸：**讓玩家的每一個操作都有意義、有價值；但「刷」同一件事沒有意義。**
> 外向的玩家透過互動、組隊得到更多；內向的玩家靠採集、建造、烹飪、種植、畜牧、釣魚也有穩定的收入與樂趣。

mana 仍然是唯一的貨幣（沿用「生生不息」企劃：沒有金幣、不講價、不比價、持有過多會歸土）。1.3.0 補上交接報告中的兩大缺口：

- **P1：mana 幾乎沒地方花** → 新增委託板手續費、社區工程投資、祭壇特別物品。
- **P2：獨自玩的人收入低、挖礦/烹飪/釣魚沒有 mana** → 新增生活手藝、圖鑑、城鎮訂單。

## 1. 三條設計原則

| 原則 | 做法 |
| --- | --- |
| **廣度勝過數量** | 「多樣性」係數：只種小麥 ×0.625，輪種 4 種作物 ×1.0。「圖鑑」只獎勵第一次。每種手藝有自己的每日上限，想拿滿就要換著玩。 |
| **有人需要，東西才有價值** | 生產的東西主要透過「城鎮訂單」（需求每天輪替）、「委託板」（別的玩家需要）、「社區工程」（全服需要）變成 mana，而不是丟進回收機。 |
| **一起玩更划算，但不強迫** | 結伴加成 +25%；合作挑戰人越多每人拿越多；城鎮訂單交滿時所有出力者都有完成獎勵（不用開口也能「一起」完成一件事）。 |

## 2. mana 從哪裡來

| --- | --- | --- | --- |

### 2.1 生活手藝的細節

- **新鮮度**：每得到 1 點下降 0.5%，最低 30%，每分鐘恢復 1%。效果：同一種手藝一口氣大概拿 14 mana 後效率剩三成，休息約 70 分鐘完全恢復。
- **多樣性**：看最近 32 次動作裡有幾種不同的東西。係數 = 0.5 + 0.125 × 種類數（最多 1.0）。
- **結伴**：32 格內有其他「非 AFK、不同網路」的玩家，點數 ×1.25。
- **等級**：經驗 = 有效點數（城鎮訂單也給經驗）。Lv1～Lv10，稱號「見習 → 生生不息」。**等級解鎖更高級的城鎮訂單**（例如金胡蘿蔔、鸚鵡螺殼、鑽石），超過每日 mana 上限後仍然累積經驗，所以多玩永遠有進度。
- **防刷**：
  - 礦石、原木、南瓜、西瓜、甘蔗、竹子、仙人掌如果是**玩家放下的**，打掉不算（記在區塊的持久資料，重啟也記得；被活塞推動時標記跟著走）。
  - 建造：點數要等方塊**在原處放滿 10 分鐘、而且還是同一種方塊**才入帳（每分鐘結算一次）；拆掉、被活塞推走、別人拆掉都不算。火把、花、作物等非實心方塊不算。
  - 合成料理：下一個 tick 比對合成格實際用掉多少才算，背包滿時的空點擊不算。
  - AFK 時不產生。

| --- | --- |
| 採集 | 礦石 1（鐵 1.5、金/青金石 2、鑽石/綠寶石 5、遠古遺骸 8）、原木 0.5 |
| 種植 | 成熟作物 1、南瓜/西瓜 1、甘蔗/仙人掌 0.5、竹子 0.25、右鍵採收漿果 1 |

| 建造 | 每個實心方塊 0.25 |

## 4. 委託板

「求助 → 幫忙 → 感謝」的循環，是外向玩家與內向玩家交會的地方：內向玩家可以默默接物品委託，交貨就完成，不必聊天。

- **物品委託**：手拿想要的物品 → `/mana board` →「發布物品委託」→ 選數量 → 選酬謝。接單的人直接從背包交貨，物品（含附魔等資料）送到發布者背包；發布者離線時暫存，上線後到「我的委託」領取。
- **服務委託**：`/mana request service <酬謝> <說明>`，例如「幫我蓋屋頂」「陪我去下界」。別人接下後，由發布者在「我的委託」Shift+左鍵確認完成，酬謝才轉過去。
- **酬謝只能選 2 / 5 / 10 / 20 / 50**：沒有講價、比價的空間。
- 取消可退回酬謝（手續費不退）；7 天沒完成自動取消並退回。每人同時最多 3 張。
- 同一網路的帳號不能互接；助人 mana 需酬謝 ≥ 5，同一對玩家每週最多 3 次。

## 7. 設定與指令

所有數值都在 `config.yml`，並有中文註解。**舊的設定檔不用改**：缺少的區塊（訂單池、社區工程、點數表…）會自動使用插件內建的預設值。要調整時，把 `src/main/resources/config.yml` 中對應的區塊複製到伺服器的設定檔，改完 `/manaadmin reload`。

| 指令 | 說明 |
| --- | --- |
| `/mana` | 選單（新增：生活手藝、圖鑑、城鎮訂單、委託板、社區工程） |
| `/mana skills`、`dex`、`orders`、`board`、`projects` | 直接開對應頁面 |
| `/mana request <數量> <酬謝>` | 徵求手上拿的物品 |
| `/mana request service <酬謝> <說明>` | 請人幫忙 |
| `/manaadmin orders [reroll]` | 查看／重新抽選今天的城鎮訂單 |
| `/manaadmin project list`、`reset <id>` | 社區工程 |

新資料表：`crafts`、`order_progress`、`order_contrib`、`commissions`、`project_state`、`project_needs`、`project_contrib`（啟動時自動建立，舊資料不受影響）。

## 8. 尚未驗證的部分（下一步）

- **沒有在實機上跑過**：這次的環境無法架 DivineMC 伺服器。程式已用 Paper 26.3 API 原始碼編譯通過、計算邏輯有單元測試，但事件觸發、選單操作、跨日切換需要在測試服實際走一遍（見 README 的「實機驗證清單」）。
- 試算的玩家行為是假設值；建議封閉測試一週後，用 `analyze.py` 的方式統計各來源的實際比例，再調整上限與點數。
- mana 出口夠不夠，取決於社區工程的規模與服主開新工程的頻率，需要觀察。
- ClaudeBot 協定限制（攻擊、移動中挖掘）讓機器人無法測試合作挑戰與採集，這兩項請找真人測。
